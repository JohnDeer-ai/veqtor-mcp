# NR-03 v3 adverse document component

This is an observer evidence policy, not a runtime/API change. Select
`expected_unavailable_journal` in the frozen observation plan's
`expected.document_policy` only for `journal-unavailable`; the other independent
write cases use `positive_complete_journal`. The wrapper checks the exact original
command, receipt, configuration, workflow, initial inventory and ancestry. These
bindings do not establish log authenticity. Historical v2 refusals stay refused.

The static port in `nr03_adverse_document.py` derives from
`check_paragraph_acceptance.py` at H `3e557e69bcc244cdf366a6c100c2590d011fb4e5`,
SHA-256 `ca9df9ca03b88c0c10c7b99e2c531275c01917097964b7f0bcf1b6337bfe5965`.
Both frozen NR-01 checker files stay byte-identical. Tests compare the actual AST
of the complete substantive block and final hash rechecks, and causally exercise
both components on passing synthetic fixtures. No historical transcript is edited.

Ordinary genuinely recovered same-scope/mode failures take precedence over the
otherwise-unresolved creation exception. Public-valid outline/browse/search,
omitted/default/bounded strict limits and mode-valid nulls are eligible only for
independently absent output discovery. Multiple discoveries and discoveries after
preflight are allowed only when completed before apply starts. Snapshot-bound
reads/cursors cannot originate from an absent snapshot. All failure events remain
in the ledger, including expected exports; an added unresolved failure refuses.

Brief coverage uses all fourteen current/previous obligations (indices 2,4,5,6,7,8,9
in each file). Full sections require fresh same-file discovery, actual membership,
complete exact pages/counts/policies/cursors and per-paragraph exact quotes.
Direct/section/mixed brief forms are permitted. Write validation retains the
frozen direct-paragraph reads. No old predicate or failed P9 pair is relabeled.

Model delivery is a separate required gate. For each assessed stage the observer
preserves the original client session prefix ending at that turn's task_complete,
and supplies `<stage>.delivery.json` with exactly `schema_version` =
`nr03-model-delivery.v3`, absolute `session_path`, `session_sha256` and
`receipt_sha256`. `nr03_model_delivery` checks identity, current turn, final message,
original call/output attribution and full matching payloads. Never construct this
artifact by synthesizing client output from MCP logs. Raw completeness with clipped
or metadata-only model output refuses. Journal presentation remains separately
assessed; complete Word evidence cannot turn a limitation into a complete export.

Run `check_next_round_observation.py --bundle … --step …` only on a separately
released new candidate observation. Its result is component-only: actual business
approval/exclusions, injection handling, truthful final limitation, journal client
presentation, full-page visible markup and aggregate native acceptance stay open.
The helper neither launches a client nor materializes dependent cases.
